# 邻域、插值与球面区域查询约定

0.2.0 为现有库新增基础空间能力，保留 0.1.0 的编号、区间、目录、地图与三个示例 API。以下边界也是测试与应用接入的依据。

## 邻域与插值

`Grid::neighbours(pixel, ordering)` 在输入和输出中使用相同编号顺序，固定返回八个槽位：SW、W、NW、N、NE、E、SE、S。七邻域像素的缺失槽为 `-1`，不能直接当作地图下标。

`bilinear_interpolation_weights(point, ordering)` 返回四个像素编号和四个非负归一化权重，使用相邻 RING 纬圈及极帽规则；输出可请求 NESTED 编号。`ScalarMap::interpolate_bilinear(point)` 使用地图自身的编号顺序。四槽中任意一个缺失值均传播为 `None`，包括权重为零的槽位；不对剩余权重重新归一化。两个极点使用四个极帽像素，各权重 0.25。精确落在中心/边界的零权重槽可能受浮点择边影响，比较应考虑加权贡献和有非零权重的像素。

独立 astropy-healpix 1.1.3 oracle 覆盖 2180 条邻域记录、3004 条插值记录及 128 条缺失值记录，含 nside 8192 极区与两种编号顺序；权重误差容限为 2e-11。普通测试直接消费固定资料。

## 区域模型

`SphericalPolygon::new` 接受至少三个球面顶点，以短大圆弧连接。顶点绕序可正可反；区域必须凸且位于一个开半球内。重复相邻顶点、反极点边、非凸或自交绕序返回错误。最多 4096 个顶点，另受调用者 `max_vertices` 限制。任意两个顶点间距小于 1e-12 弧度或接近反极点到该余量以内时拒绝；边的内部方向和严格半球判定有 1e-14 的数值非退化门限。顶点平均方向用于定绕序，分隔半球由内向边法线之和验证，避免误拒绝宽三角形。闭合边用 1e-14 单位向量点积余量吸收浮点舍入。不支持凹多边形、洞或面积超过半球的任意多边形。

`query_polygon` / `search_polygon` 选择中心落入上述半空间的像素，输出 NESTED `PixelSet`。`search_disc` 与旧 `query_disc` 的闭球面圆中心语义相同，输出顺序分别为 NESTED 和 RING。新 `PixelSearch::visited()` 报告实际访问的层级节点数。

## 曲边像素足迹覆盖

`cover_disc` / `cover_polygon` 返回 `RegionCover`，而不是把中心查询改名为相交查询：

- `pixels()` 是保守相交候选集合，包含所有实际相交的像素，也可能含未相交的边界像素。
- `interior()` 中的像素整个足迹确定在区域内。
- `boundary()` 是两者之差，表示尚不能排除相交的像素。调用者不能把它们当成已证明相交。
- `refine_levels` 为 0..(13 - 目标 order)，在原像素内细化到指定阶，线性细化因子为 `2^refine_levels`。细化仅排除已证明不相交的子单元；不会删除真实相交像素。预算耗尽返回 `ResourceLimit`，不返回悄悄截断的结果。

这与成熟生态的 inclusive 查询用途一致，但不承诺返回与 healpy `inclusive=True` 完全相同的候选集合或 `fact` 误差。当前没有解析的任意曲边像素精确求交器；细化到最大 order 后仍须把未决边界作为保守候选处理。零半径圆支持接触角点的足迹候选，与通常为空的像素中心集合有意区分。

## 包围球保证与剪枝

`Cell::bounding_radius()` 不依赖边界点采样。连续面投影在极区为线性分式经度、赤道区为线性经度；每段凸域的经度极值出现在顶点，包括极区与赤道过渡线和像素边的交点。纬度随面坐标之和单调，两个对角给出纬度极值。极点处纳入整个基本面楔形的经度极限。

从中心沿其纬圈走到目标经度，再沿子午线到目标纬度，路径长最多 `cos(center_lat) * max_delta_lon + max_delta_lat`；最短球面角距不超过这条路径长。加上浮点余量得到包围半径。圆查询用球面三角不等式剪枝；凸多边形用各大圆半空间的带符号角距离剪枝。完整包含的粗单元直接写成连续后代区间，避免逐像素扫描。

该半径有意宽于最小包围半径；没有把样本检查当成连续数学保证。独立 astropy 坐标样本另用于回归投影与极区实现。

## 稀疏源目录

`Catalog` 在 NESTED 排序分箱之上建立平衡包围球树。叶子包围真实输入源；父球通过球面三角不等式包围子球，近反极点退化时退回全球上界。检索先排除不相交节点，再对保留源作精确角距离过滤，按距离与输入编号稳定排序。

`search_cone` 提供 `visited_nodes()` 和 `tested_sources()`，旧 `query_cone` 复用同一树。`max_work` 现为节点访问加实际源距离测试总数；这会影响同一数值预算能完成的查询，但不会改变成功查询的源集合。最坏情况下仍可访问整个目录；计数是可复现的工作量证据，不是跨库速度排名或硬时间沙箱。

## 标准互操作边界

空间 MOC 采用 IVOA MOC 2.0 第 4.3.2 节的 ASCII 编码与附录 F 的信息性 JSON 编码。限定 ICRS、NESTED、order 0..13；调用方负责确保输入方向属于 ICRS，本库不做天球坐标系变换。FITS、时间、频率、时空 MOC 和更高阶不在当前范围。

`Moc` 内部保存规范化的 order 13 区间和独立的最大阶元数据，空覆盖、兄弟折叠后仍保留最大阶。`equals` 比较覆盖集合；需要元数据相等时还应比较 `max_order()`。构造器可归并重叠单元，文本解析器明确拒绝重复/重叠单元、无序索引、畸形结构与超限数据。默认资源上限为 100000 个候选区间、100000 个实体单元、4194304 个 ASCII 文本字符，可经 `MocLimits::new` 降低但不能提高硬上限。

`from_pixel_set` 要求 NESTED，降到声明阶时必须精确对齐。`pixel_set()` 返回 order 13 的独立集合；`union/intersection/difference/complement` 保留集合语义，预算在归并之前检查候选。ASCII 使用范围以避免大区间逐单元展开；JSON 需要实体单元列表，可能因输出限制失败。MOC 编码只说明像素覆盖，不能把保守区域候选转成精确相交结论。

mocpy 0.21.0 独立读取实际 MoonBit 输出的 182 份 ASCII 和 182 份 JSON，逐一验证覆盖区间、NUNIQ 和最大阶。另对赤道、接缝、南北极四个多边形的候选/内部/边界/中心集合验证 16 组双编码转换；这是 MOC 转换验证，不证明双方几何边界策略相同。
